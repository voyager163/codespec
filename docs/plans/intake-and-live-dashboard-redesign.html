      What changed vs. today's dashboard

      • Compliance bar is read-only with a lock — the agent scores it; the manual number input is gone.
      • Header carries the project name + storage key; the story / objective / pain ride along as a context strip.
      • Each working agent shows its live source (the real Claude Code process + stream), not a scripted timer.
      • The status pill reads live · SSE and real engines — see the next tab for how that's wired.
      The live-status gap

      Today the dashboard polls /api/state every 1.2s and that state is derived from an append-only event bus. The problem: the events are written by a simulated loop (tools/lifecycle/lib/loop.js) that emits hardcoded messages on a setTimeout. Real Claude Code agents never write to the bus, so the page shows a convincing demo — not live work.

      The fix — bridge real agents into the bus you already have

      The server already exposes POST /api/emit. Nothing calls it. Wire the real agents to it and the existing dashboard becomes genuinely live with no UI rewrite.

      Claude Code agent→ hook / wrapper→ POST /api/emit→ status bus (append-only)→ SSE push→ dashboard
      Concrete steps
      • Emit from real runs. Add a thin reporter that each spawned Claude Code agent calls (a PostToolUse / Stop hook, or a wrapper around the agent invocation) which POSTs {rotation, stage, agent, level, message, data} to /api/emit. The bus + deriveState already understand that shape.
      • Drop polling, add push. Replace the 1.2s setInterval(poll) with a Server-Sent Events endpoint (/api/stream) that flushes a new state on every bus append. The "live · SSE" pill turns green only while the stream is connected.
      • Map real stages → agents. Keep the existing AGENTS stage mapping; tag each emit with the real OS process id / stream so each card can show "live from claude-code pid …" instead of a fake progress bar.
      • Default to real. Flip simulate off for live runs; keep --demo for the scripted walkthrough so the demo path still exists.
      • Freshness watchdog. If no event arrives for N seconds while an agent is "working", show a stale badge instead of a forever-spinning bar — so "live" never lies.
      Files this touches
      • lib/server.js — add /api/stream (SSE); intake action stores project name + story/objective/pain.
      • lib/control.js + lib/state.js — extend intake to {projectName, userStory, objective, painPoint, repo}; compliance becomes agent-computed only (remove the editable input path).
      • assets/dashboard.html — split into intake screen → dashboard; SSE client; read-only compliance; live-source line per agent.
      • new lib/reporter.js + a Claude Code hook — the bridge that turns real agent activity into /api/emit calls.

      This is a mockup for review — no real data is sent anywhere. Tabs above switch between the proposed intake screen, the redesigned dashboard, and this wiring plan.
