Using PowerCodex on a pre-existing app

You asked two things: (1) is the tool finished enough to run development on your existing app, and (2) can it read your existing repo and produce user stories + an MVP from what it sees — which you then correct, the AI refines, and it gets frozen until a future major change. This plan answers both honestly and shows exactly what would change to make #2 real: current behaviour vs the proposed behaviour, side by side.

2What "import" does today — proof

From tools/lifecycle/lib/import.js the import only reads metadata: it looks at package.json dependencies to guess the runner (Vite/Next), checks for Power Platform marker files, writes .powercodex/config.json, and wires a cockpit script. From tools/lifecycle/lib/mvp.js + compliance.js, the MVP and the "compliance score" are built purely by tokenising your goal string. No file under src/ is ever opened.

3The workflow you want

Point at existing repo→ Read the code→ Derive user stories + MVP→ You check & fix→ AI refines from your edits→ Freeze (untouched until next major change)

4Change A · Code-aware ingestion (import --analyze)

Current
  • Reads only package.json metadata — deps, scripts, marker files.
  • Never opens src/, routes, or components.
  • Output is config + scaffolding, no understanding of features.
Proposed
  • New --analyze flag walks src/: routes/pages, components, connectors/data calls, npm scripts.
  • Produces a repo digest at .powercodex/digest.json — a structured map of what the app already does.
  • Digest becomes the grounding input for stories + MVP (no hallucinated features).

5Change B · Generate user stories & MVP from the code

Current
  • MVP = keywords from your one-line goal.
  • No user stories at all.
  • Compliance = does the MVP text echo the goal's words.
Proposed
  • Stories + MVP derived from the repo digest (real surfaces, real data).
  • New artifact .powercodex/stories/stories.json + readable stories.html.
  • Each story cites the file(s) it came from, so you can verify it.
  • Compliance also scores stories ↔ code and MVP ↔ stories.

6Change C · Review → refine → freeze

Current
  • Re-propose from a prompt; nothing is ever "final".
  • No record of your manual corrections.
  • No lock — any run can overwrite.
Proposed
  • You edit stories/MVP (in the dashboard or the files); edits are kept.
  • AI refines against your edits rather than regenerating from scratch.
  • An Approve & Freeze action sets status:"frozen" — the loop reads but never rewrites it.
  • A future Unlock for major change action is the only way back in.
This is exactly the "saved and never touched again until there is a need" behaviour you described — implemented as an explicit freeze flag the loop respects, not an honour system.

7Build order

  1. Repo digest — add the code walker behind import --analyze; write digest.json. (Foundational; everything else reads it.)
  2. Stories + MVP from digest — new stories.js; make mvp.js accept the digest instead of just the goal string.
  3. Freeze/lock state — add status to the stories/MVP files; teach the loop and dashboard to honour it.
  4. Refine-from-edits — diff your edits into the provider prompt so the AI improves rather than replaces.
  5. Self-test coverage — extend selftest.js so the 53 checks grow to cover ingestion, freeze, and refine.
  6. (Later) real engines — wire Playwright-for-MDM so Build/Run/Test stop being simulated.
