Organize the workspace

Today the codespec repo mixes three things at its root: the tool, the tool's own dev specs, and project + runtime data that belongs to specific apps. This plan separates them so PowerCodex carries no stray project code, every project owns its own openspec, and there is exactly one shared Learning_Experience brain.

🧠
The rule. One shared Learning_Experience/ at the workspace root — every project reads & writes it, so a lesson from project A helps project B. Everything else is per-project: each app under projects/ owns its openspec/, its .powercodex/ runtime, and its Approved_rights/ consent. The root openspec/ stays — it is the tool's own dev project.

The runtime already supports this: workspace.js walks up to the marker and resolves the shared brain, and paths.js computes .powercodex/ + Approved_rights/ relative to whatever root the lifecycle runs in. Running it with a project dir as root already produces per-project runtime — the reorg is mostly moving files + adding the marker.

Runtime ask 1 — verify the MDM browser profile once

Profile is confirmed one time, then reused

The pointer is committed; the session data is gitignored — credentials never enter git.

1
First MDM run for a project: runtime reads Approved_rights/approval.json → browserProfile is empty.
2
Verify once. Launch managed Edge with a named profile; you sign in / clear MFA in that window once.
3
Persist a pointer. Write browserProfile:"mdm-edge" and profilePath:"./.profiles/mdm-edge" to approval.json. The real profile dir lives in .profiles/ which is gitignored. ● cookies never committed
4
Every later run reuses the stored profile path — no re-login. It re-checks validity first; if the session expired it re-verifies once and moves on.
Runtime ask 2 — capture the app URL after push

Grab the URL from npx power-apps push and store it

So the E2E tester always knows where the live app is, without you pasting it each run.

1
Runner pushes with npx power-apps push (Dataverse connected) and parses the returned app link.
2
Persist it to the project: Approved_rights/approval.json → appUrl (safe to commit — it is not a secret), plus a push history line in .powercodex/runtime.json.
3
E2E tester reads appUrl as the base URL for every spec — replacing the hard-coded 127.0.0.1:5173 assumption.
4
Today's gap: the runner emits "got app link" but never stores the URL. This wires that through.
