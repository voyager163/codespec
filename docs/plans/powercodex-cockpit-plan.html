The Hermes-inspired redirection

A new direction for PowerCodex: an importable lifecycle you add to any repo, a bring-your-own-AI bridge so you talk to Claude Code or GitHub Copilot from one place, a plan viewer that pops open the HTML plan the moment the agent finishes it, and — replacing the localhost dashboard — a real terminal cockpit with multiline editing, slash-command autocomplete, history, interrupt-and-redirect, and streaming tool output.

The four changes

What you asked for, as one product

Today PowerCodex serves a static dashboard at localhost:4321 for one workflow. The v2 direction turns it into a portable cockpit you can carry between projects and point at any AI. Four moves:

01
📦

Import into any project

One command copies the PowerCodex core, lifecycle loop, and consent gate into an existing repo and wires up scripts — so the same loop runs the rest of that project, Power Platform or not.

02
🔀

Talk to the AI of your choice

A provider layer (Hermes-style) lets you switch between Claude Code and GitHub Copilot with /provider — same cockpit, same lifecycle, different brain behind it.

03
📄

View the plan the instant it's ready

When the agent finishes generating an HTML plan, the cockpit announces it and offers /plan open — the rendered plan opens in your browser, no hunting for files.

04
⌨️

A real terminal, not a web page

The localhost HTML view is replaced by a full TUI cockpit: multiline editing, slash autocomplete, scrollable conversation history, interrupt-and-redirect, and live streaming tool output.

⌨️ Multiline editing

⌥⏎ / Shift-↵ inserts a newline; ↵ sends. The composer grows as you type — paste a whole spec without it firing early.

🕑 Conversation history

↑/↓ recalls previous prompts, Ctrl-R fuzzy-searches the transcript. History persists per project across sessions.

⏸ Interrupt & redirect

Esc stops the agent mid-stream without losing context — you type a correction and it picks up from where it was.

📡 Streaming tool output

Edits, browser steps, and e2e assertions render inline as they happen — the same live event bus that fed the old dashboard, now in the terminal.

How the bridge works

  • Each provider is an adapter exposing one interface: send(), stream(), tools().
  • Claude Code adapter drives the Claude Agent SDK / CLI.
  • Copilot adapter drives the GitHub Copilot CLI (gh copilot / agent).
  • Auth is delegated — you log in with each vendor's own CLI once.

Why route through the cockpit

  • One transcript, history, and slash palette regardless of brain.
  • The lifecycle loop + consent gate wrap both equally.
  • Compare answers: ask Claude, switch, ask Copilot, keep the better edit.
  • Adding a third provider later is just one more adapter file.

Rollout

How we'd build it

Sequenced so each phase is usable on its own. Phase 1 already gives you the cockpit over the existing loop; later phases add portability and the second provider.

  1. Cockpit shell over the current loop

    Build the TUI (composer, slash palette, history, streaming) and point it at the existing lifecycle + status bus. Default provider: Claude Code. The localhost page becomes optional.

  2. Provider adapter layer + Copilot

    Extract the AI calls behind the send/stream/tools interface, add the GitHub Copilot adapter, wire /provider hot-swap with transcript hand-off.

  3. Plan registry + viewer

    Have the agent append to plans/index.json on every HTML plan, add the plan-ready card, and /plan open · list · diff backed by the existing static server.

  4. Portable import

    Build npx powercodex import: detect stack, vendor core, scaffold consent + registry, pick providers, wire the script. Local-run fallback for non-Dataverse repos.

  5. Self-test the new surface

    Extend the existing self-test so the cockpit, provider swap, plan registry, and the rights gate are all asserted headlessly — same bar as today's 16/16 loop checks.

The finale · how PowerCodex actually feels to use

Comfort, not compromise

Not everyone loves a terminal. So it's optional.

You said it well — the terminal is fast and powerful, but it can feel intimidating. The fix isn't to pick one or the other. PowerCodex runs one engine behind two surfaces, and you flip between them whenever you like. The graphical surface is the dashboard you already liked — with terminal power tucked into a drawer.

🪟 Studio · graphical ⌨️ Cockpit · terminal

One keystroke (⌘\) or the toggle in the corner swaps the surface. Same project, same loop, same consent gate, same live data underneath.

🪟

Studio — recommended default

The exact dashboard look you liked: intake, rights chips, the 7-stage loop strip, agent cards, live feed, coverage ring. Everything is a button or a click — no command memorisation. And a terminal drawer sits at the bottom for the moments you want raw speed.

⌨️

Cockpit — for power users

The full TUI from the screenshots above. Keyboard-only, fastest possible. Everything the Studio buttons do maps to a slash command here, so muscle memory transfers either direction.

The key idea: the graphical Studio doesn't lose terminal power — it embeds it. The bottom drawer is a real terminal driving the same agent. Beginners never have to open it; power users live in it. Same app, your comfort level.

Capabilities

Everything PowerCodex can do

The same toolbox is available from both surfaces — a button in Studio, a slash command in the Cockpit. Grouped by what you're trying to get done.

🔁 Lifecycle & orchestration

Drive the 7-stage loop that owns the whole build.

  • /start · /pause Run or hold the loop; pauses land on the next safe gate.
  • /loop --rotations Iterate — each rotation re-plans from what the last one observed.
  • /reflect Log a lesson into Learning_Experience mid-run.
  • /reset Clear the run state and start fresh.
🛠️ Build & test engines

The two MDM engines that build and verify the app.

  • /build Engine 1 drives Edge against the tenant — or npm run dev locally.
  • /run Launch the app so it can be exercised.
  • /test Engine 2 runs e2e checks and powers self-heal.
  • /push Ship to the tenant — gated on the push right.
🔀 AI providers

Bring your own brain; the loop wraps all of them.

  • /provider Switch between claude-code & github-copilot mid-session.
  • /model Pick a model within the active provider.
  • /compare Ask both, keep the better edit.
📄 Plans & specs

See what the agent intends before it acts.

  • /plan open View the latest HTML plan in the browser.
  • /plan list · diff Browse every plan and compare versions.
  • /approve Endorse a plan or an observed spec → build.
🔒 Consent & safety

Nothing touches your tenant without permission.

  • rights chips Toggle build / push / auto-respec / auto-fix.
  • /gate Inspect exactly why a step is blocked.
  • compliance Goal↔MVP meter keeps the build honest.
📦 Projects & portability

Carry the cockpit between repos.

  • powercodex import Add PowerCodex to any existing repo.
  • /new Create a fresh project from a goal.
  • /open Switch between projects in the workspace.
