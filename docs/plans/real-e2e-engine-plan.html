Change A — vendor the engine + an optional-dependency bridge

Now

  • engines.js has placeholder buildExecutor / e2eTester / verifyProfile that emit the right event stream with simulate:true outcomes.
  • Zero dependencies. No browser is ever launched.
  • The real engine lives only in ~/Downloads/Playwright-for-MDM-Browser/ — ESM, depends on playwright.

New

  • Vendor attach.js into the repo at tools/lifecycle/engine/mdm-attach.mjs (kept ESM, mirrored into the starter template).
  • New lib/engines.real.js — loads the vendored engine with a lazy import() (CJS→ESM), exposes real verifyProfile + e2eTester, and reuses one CDP session across rotations.
  • playwright stays optional: the npm package keeps its zero-dependency guarantee. You install it only to go real: npm i -D playwright.

Change B — resolve real vs. simulate, recommend Playwright by default

Now

  • loop.js statically imports the simulated engines.
  • --real exists but only flips text and rights-gating; nothing actually drives a browser.
  • No signal to the user that real engines are even possible.

New

  • New resolveEngines(root, {simulate, emit}) picks the engine bundle at run time.
  • New lib/playwright-check.js decides if the project is browser-based (Power Platform tenant, or has web routes/components/dev-server — read from the digest).
  • When real is requested but Playwright is missing: if browser-based → emit a clear "install Playwright" recommendation and fall back to simulation gracefully; if not browser-based → use simulation quietly, no nag.
  • The recommendation also surfaces in import --analyze, the dashboard banner, and /api/state.

Decision logic (your requested rule, made concrete)

if (--real requested)
    if project is not browser-based → simulate quietly (no Playwright nag)
  elif Playwright not installed → recommend "npm i -D playwright" + simulate
  else → real engine: attach to managed Edge, run real smoke tests

Change C — honest self-heal & escalation in real mode

Now

  • After a (simulated) failure, the loop re-runs and unconditionally emits "Green" — fine for simulation, where the second run is rigged to pass.

New

  • The green emit becomes conditional. A real app that is still broken after the self-heal attempt emits "Still red after self-heal · escalating to you" and stops — no false green.
  • The no-progress guardrail (same failure twice → stop) now catches genuine, repeatable real failures.

What you'll run

1
npm i -D playwright — once, in the app you want to drive for real (PowerCodex recommends this when it sees a browser-based project).
2
npm run lifecycle -- import --analyze — so the loop knows the project is browser-based and where the app lives.
3
Sign in once in the managed Edge profile (MFA cleared in the window) — the session persists; later runs reuse it.
4
npm run lifecycle -- loop --real --app-url https://<your-app> — attaches to your live Edge, navigates the app, and reports real browser health.
