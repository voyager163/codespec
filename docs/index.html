PowerCodex turns a plain-language goal and an approved MVP into a running app — then keeps it healthy. What it is

One loop that owns the whole build

Most tools help you write code. PowerCodex runs the entire lifecycle around it — from understanding the goal to healing the app after it ships — as a single, observable loop. It takes two inputs and produces a working, continuously-verified app.

Input 1 · The goal

A plain-language description of what the app should do. "A leave-request app where staff submit time off and managers approve it."

Input 2 · The approved MVP

The slice you've agreed to build first. PowerCodex measures everything it does against it with a live goal↔MVP compliance meter.

🔁

Autonomous, not blind

It runs the loop on its own, but stops at a consent gate before anything that touches your tenant.

📡

Always observable

Every stage, agent, and event streams to a live dashboard. Nothing happens off-screen.

🩹

Self-healing

When a test goes red, the e2e engine diagnoses it, writes a spec from the observation, and re-builds.

The loop

Seven stages, one rotation

Each rotation moves through seven stages. The dashboard highlights the current stage live and advances an overall progress bar; when a rotation ends, observations feed the next one.

The Approve stage is a real gate, not a formality. PowerCodex reads Approved_rights/ before it builds or pushes. If the relevant flag (build / push / auto-respec / auto-fix) is false, the loop blocks right there and waits for you.

Under the hood

Two engines and a status bus

🛠️

Engine 1 · Build Executor

Drives a managed Edge browser against the Power Platform tenant to build the app from the plan — or runs locally via npm run dev when there's no Dataverse.

🧪

Engine 2 · E2E Tester

Runs end-to-end tests against the running app and powers the self-heal loop when something breaks.

Both engines emit a real event stream onto an append-only status bus (.powercodex/live/status.json). The dashboard server reads that bus and serves /api/state; the page polls it every 1.2s and re-renders in place.

How to use it

Open the dashboard, then run the loop

PowerCodex ships as a small zero-dependency Node tool with npm scripts. The flow is always the same: start the live dashboard and leave it open, then drive the loop in a second terminal — the dashboard follows along.

  1. Initialize the workspace

    Creates .powercodex/live/, the Approved_rights/ consent file, and a first dashboard snapshot.

    # one-time setup in your project root
npm run lifecycle -- init

  2. Grant the rights you're comfortable with

    Open Approved_rights/approval.json and set the flags — build, push, auto-respec, auto-fix. The loop will only ever do what you've turned on.

  3. Start the live dashboard — keep it open

    A zero-dependency server serves the dashboard at localhost:4321 and a /api/state endpoint. Add --demo to drive a paced simulated loop so you can watch it move.

    npm run lifecycle:serve              # http://localhost:4321
npm run lifecycle:serve -- --demo     # also drives a paced demo loop

  4. Run the loop in a second terminal

    The open dashboard follows along live — stages light up, agent cards update, the activity feed streams newest-first.

    npm run lifecycle -- loop --rotations 3
npm run lifecycle -- loop --rotations 2 --real   # real engines (needs tenant + rights)

  5. Prove it works against itself

    The self-test runs the full loop in a throwaway workspace and asserts the product does what the plan promises — 16/16 checks, including the rights gate blocking an un-approved build.

    npm run lifecycle:selftest           # 16/16 checks

Honest by default

What's real vs. simulated

The orchestration, consent gate, status bus, and live server are all real. The two engines drive a managed browser against a production tenant — which can't run without a tenant + MFA — so they ship as adapters with a simulation fallback. Swap two functions in lib/engines.js and nothing else changes.
