1 Installation & Setup

The fastest way to register the MCP server is with the built-in install command. One terminal line is all you need.

Quick install — Claude Code

Run this from your project directory. It calls claude mcp add for you.

# From this repo (local install)
npm run install-powercodex-mcp

# Or via npx — no clone needed (once published to npm)
npx @elfredseow/powercodex install-powercodex-mcp

That registers the server at project scope (saved to .claude/settings.json). To register it for all your projects instead:

npm run install-powercodex-mcp -- --user
# or
npx @elfredseow/powercodex install-powercodex-mcp --user

To point the server at a different project root than the current directory:

npx @elfredseow/powercodex install-powercodex-mcp --root /absolute/path/to/project
What the command does

It runs claude mcp add --scope <scope> --env POWERCODEX_ROOT=<root> powercodex node /path/to/powercodex-mcp.mjs under the hood, then prints a confirmation. Restart your AI host to activate.

Manual — claude mcp add (Claude Code CLI)

If you prefer to type the raw claude command yourself:

# Project scope (writes to .claude/settings.json in your project):
claude mcp add --scope project \
  --env POWERCODEX_ROOT=$(pwd) \
  powercodex node $(pwd)/bin/powercodex-mcp.mjs

# User scope (available in every project):
claude mcp add --scope user \
  --env POWERCODEX_ROOT=$(pwd) \
  powercodex node $(pwd)/bin/powercodex-mcp.mjs

Claude Desktop (JSON config)

Claude Desktop doesn't support the CLI installer. Edit ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) or %APPDATA%\Claude\claude_desktop_config.json (Windows): 

{
  "mcpServers": {
    "powercodex": {
      "command": "npx",
      "args": ["-y", "@elfredseow/powercodex", "mcp"],
      "env": { "POWERCODEX_ROOT": "/absolute/path/to/your/project" }
    }
  }
}
Verify the connection

After restarting your host, ask Claude: "List my pac auth profiles." If it responds with profile data (or "no profiles found"), the server is live.

2 Scaffold Tool

Creates a new PowerCodex project (Vite + React + TypeScript + OpenSpec + pac) in one call.

scaffold_project tool

Runs create-powercodex.js to set up a fully wired project directory. After scaffolding, run npm install inside the new directory (unless skipInstall is true).

PARAMETERTYPEDESCRIPTION
name string required App name in kebab-case (e.g. inspection-app)
targetDir string required Absolute path to the parent directory where the project folder is created
skipInstall boolean optional Skip npm install — faster but leaves node_modules absent. Default: false
skipGit boolean optional Skip git init. Default: false

Example prompt

-- Tell Claude:
Scaffold a new PowerCodex project called "site-inspection" in "/Users/me/projects".

Claude will call scaffold_project with name="site-inspection" and targetDir="/Users/me/projects". The project is ready at /Users/me/projects/site-inspection.

dataverse_init_schema tool

Creates .powercodex/dataverse-schema.json with a starter template. Safe to call when the file already exists — it won't overwrite.

projectDir string optional Absolute path to the project root. Defaults to the POWERCODEX_ROOT the server was started with.
displayName string optional Display name for the first table in the template. Default: "MyTable"
pluralName string optional Plural display name. Defaults to displayName + "s"
dataverse_apply_schema tool

Reads .powercodex/dataverse-schema.json and drives a managed Edge browser to create any tables and columns not already present in the environment. Results (including captured logical names) are saved to .powercodex/dataverse.json.

Browser automation

With dryRun: false (the default) this opens a real browser window and makes live changes in your Power Platform environment. Use dryRun: true to preview actions first.

projectDir string optional Absolute path to the project root.
environmentId string optional Power Platform environment GUID. Uses the default environment if omitted.
dryRun boolean optional Log what would be done without opening the browser. Default: false
dataverse_get_state tool

Returns the current .powercodex/dataverse.json — the applied state including logical names captured after the last apply run.

projectDir string optional Absolute path to the project root.

Example prompts

-- Create a schema template for an "Inspection" table:
Init the Dataverse schema with a table called "Inspection".

-- After editing dataverse-schema.json, apply it:
Apply my Dataverse schema. Do a dry run first so I can see what will change.

-- Check what was actually created:
Show me the current Dataverse state for this project.
4 Lifecycle Tools

The lifecycle loop is the core of PowerCodex automation. It runs rotations: each rotation builds the app, runs tests, and (in non-manual modes) attempts to self-heal failures.

manual

Manual fix-mode

Loop stops if tests stay red after build. You fix manually.

diff

Diff fix-mode

Loop pauses at the fix and returns awaiting_approval; call approve_fix or reject_fix to continue.

auto

Auto fix-mode

Loop keeps attempting fixes up to maxHealRetries without interruption.

start_lifecycle_loop tool

Starts the lifecycle loop as a background session and streams events as MCP progress notifications. The call returns at the first checkpoint — either when the loop reaches an approval gate (status awaiting_approval, with a resumeToken) or when it completes (complete / stopped / error). It does not block across a human pause, so it stays well within host request timeouts. Drive a paused loop with approve_fix / reject_fix, and follow it with get_lifecycle_state.

goal string optional Plain-English description of what the app should do. Passed to the AI planner.
rotations integer 1–20 optional Number of build-test cycles to run. Default: 1
fixMode enum optional manual | diff | auto. Default: manual
maxHealRetries integer 1–10 optional Max self-heal attempts per rotation (auto mode only). Default: 3
maxDurationMs integer optional Wall-clock cap. The loop stops cleanly at the next rotation/approval boundary when exceeded (browser released). Default: 600000
real boolean optional Use real managed Edge browser for smoke tests. Requires Playwright. Default: false (simulated)
appUrl string optional Live app URL for real e2e smoke tests (only used when real: true)
environmentId string optional Power Platform environment GUID
projectDir string optional Project root. Defaults to POWERCODEX_ROOT
approve_fix tool

Resumes a loop that returned awaiting_approval (build approval or diff fix-mode). Approves the pending change; the call returns at the next checkpoint — another gate, or completion.

Timing

Call approve_fix after start_lifecycle_loop returns awaiting_approval — as a separate tool call. Each call is short and never spans the human pause, so host request timeouts are never an issue. The session lives in the server, keyed by projectDir.

projectDir string optional Must match the projectDir passed to the running loop.
reject_fix tool

The counterpart to approve_fix: declines the pending fix/build so the loop stops cleanly instead of proceeding. Use it when the diff isn't acceptable.

projectDir string optional Must match the projectDir passed to the running loop.
get_lifecycle_state tool

Reports the current background session — status (running / awaiting_approval / complete / stopped / error) plus any new events since you last looked. When no session is active it falls back to the persisted bus.json on disk. Use it to poll a long real-mode run.

projectDir string optional Project root.

Example prompts

-- Run 3 rotations in auto-heal mode:
Run the lifecycle loop for 3 rotations in auto fix-mode with up to 5 heal retries.

-- Use diff mode and approve a fix interactively:
Start the lifecycle loop in diff mode. When you show me a diff, I'll tell you to approve it.

-- Check what the loop is currently doing:
What is the current lifecycle state?
5 PAC (Power Apps Code App) Tools

These tools wrap the pac CLI to authenticate, scaffold, and deploy a Power Apps Code App. The typical sequence is: authenticate → initialise → build → push.

initialize_code_app tool

Runs pac auth (if an environment URL is given) followed by pac code init to scaffold the Power Apps Code App entry point. This is the "quick start" step.

appName string optional Display name for the Code App. Default: "MyPowerApp"
environmentUrl string optional Power Platform environment URL. If provided, triggers pac auth before init.
outputDir string optional Where to create the scaffold. Defaults to {projectDir}/src
projectDir string optional Project root. Defaults to POWERCODEX_ROOT
push_code_app tool

Runs pac code push to deploy the built app bundle to Power Apps. You must run npm run build before calling this tool.

appDir string optional Directory containing the built app. Defaults to {projectDir}/src
projectDir string optional Project root. Defaults to POWERCODEX_ROOT
list_pac_auth tool

Lists active pac auth profiles so Claude knows which environments are already authenticated. No parameters.

Example prompts

-- Show which environments are authenticated:
List my pac auth profiles.

-- Initialise a Code App and authenticate in one step:
Initialize a Code App called "SafetyCheck" against
environment "https://myorg.crm.dynamics.com".

-- Deploy the app after building it:
Push the Code App to Power Apps.
6 MCP Resources

Resources are readable URIs that the host can fetch at any time without calling a tool. They are useful for giving Claude an up-to-date snapshot of project state.

URI Type Description
powercodex://lifecycle/state resource Live lifecycle bus state — current stage, last events, scores. Returns {"status":"idle"} when no loop has run.
powercodex://plans resource JSON list of all registered plan documents in the project.
powercodex://plans/{id} resource Full HTML content of the plan identified by {id}. Returns a 404-style message if not found.

Using resources in Claude

In Claude Desktop or Claude Code, resources appear in the "Attach" panel. In API usage, fetch them via the MCP resource read call. You can also ask Claude directly:

-- Ask Claude to read the live lifecycle state:
Read the lifecycle state resource and tell me what stage the loop is in.

-- Browse available plans:
List all plans registered in this project.
7 OPSX Prompts

The server automatically discovers every .md file inside .github/prompts/ and registers it as a named MCP prompt. These OPSX workflow prompts can be injected into a conversation at the click of a button in supporting hosts (Claude Desktop, Cursor).

Naming convention

A file named .github/prompts/deploy-to-staging.md becomes the prompt opsx_deploy_to_staging. Non-alphanumeric characters are replaced with underscores and the name is lowercased.

Adding a new OPSX prompt

Create the file

Add a .md file to .github/prompts/ with your workflow instructions.

Restart the MCP server

The prompts are discovered at server startup. Restart your AI host or reload the MCP server to pick up new files.

Select the prompt in your host

In Claude Desktop, open the prompt picker and search for opsx_. In Claude Code, reference it by name.

New project from scratch

Scaffold the project

"Scaffold a project called inspection-app in /Users/me/projects" → scaffold_project

Init Dataverse schema

"Init the Dataverse schema with a table called Inspection" → dataverse_init_schema

Edit schema, then apply

Edit .powercodex/dataverse-schema.json, then "Apply my Dataverse schema" → dataverse_apply_schema

Initialise Code App

"Initialise a Code App called InspectionApp against https://myorg.crm.dynamics.com" → initialize_code_app

Build & push

Run npm run build, then "Push the Code App to Power Apps" → push_code_app

Iterative development with auto-heal

-- 1. Describe the goal and kick off a multi-rotation auto-heal loop:
Run the lifecycle loop for 5 rotations in auto fix-mode.
The goal is: "Users can submit inspection reports and view them in a gallery."

-- 2. After the loop, check Dataverse state to see captured logical names:
Show me the current Dataverse state.

-- 3. Deploy:
Build and push the Code App.

Supervised diff-mode workflow

-- Start in diff mode — Claude will pause at each fix and show a diff:
Start the lifecycle loop in diff fix-mode with 3 rotations.

-- When Claude reports a diff event, review it and then:
Approve the fix.        ← calls approve_fix, loop continues
9 Troubleshooting
SymptomLikely causeFix
MCP server not appearing in host Wrong path or config JSON syntax error Verify the absolute path to powercodex-mcp.mjs and validate JSON in the config file.
dataverse_apply_schema opens no browser Playwright not installed Run npx playwright install chromium in the repo root.
initialize_code_app fails with "pac not found" pac CLI not on PATH Install from aka.ms/PowerAppsCLI and ensure it's on your shell PATH.
approve_fix returns "No loop is waiting" Loop already finished or wrong projectDir Make sure start_lifecycle_loop is still running and both calls use the same projectDir.
OPSX prompts not appearing No .github/prompts/ directory or server not restarted Create the directory, add .md files, then restart the MCP server / reload the host.
powercodex://lifecycle/state returns {"status":"idle"} No loop has run yet in this session Run start_lifecycle_loop first. State persists only for the server's lifetime.
Loop stops immediately in manual mode Tests are red and fix-mode is manual Fix the failing tests manually, or switch to diff or auto fix-mode.
Checking logs

Every tool returns a full event log in its text response. If something fails, read the Log: section in the tool output — it contains per-stage messages at [info], [warn], and [error] levels.
