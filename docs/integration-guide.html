Integration guide

Add the Lifecycle to an existing project

A nine-step walkthrough to drop the PowerCodex autonomous lifecycle loop into a codebase you already have — so you get the consent-gated build/run/test/observe loop and the desktop app without changing how your project is structured. Every step is copy-paste and reversible.

Zero dependencies. The tool is plain Node — no install, no build step, no lockfile churn. Integration is copying a folder and adding three npm scripts.
1 Check prerequisites

What your project needs

  • Node.js 18+ — the tool uses node: core modules only (fs, path, http).
  • A package.json — so you can add the three npm scripts. Run npm init -y first if you don't have one.
  • A free port — the desktop app boots the lifecycle server on a free port automatically.
  • Optional · a Power Platform tenant — only needed later for the --real engines. Everything runs in simulation without one.
2 Copy the tool in

Drop in tools/lifecycle/

Copy the entire tools/lifecycle/ folder from PowerCodex into your project. It's self-contained — keep the internal structure intact.

tools/lifecycle/
├── bin/
│ └── powercodex-lifecycle.js # the CLI entry point
├── lib/
│ ├── loop.js # the 7-stage orchestrator
│ ├── engines.js # the two engines (swap for real later)
│ ├── rights.js # the consent gate
│ ├── server.js # the lifecycle server (booted by the desktop app)
│ ├── dashboard.js · bus.js · state.js · paths.js · selftest.js
├── assets/chat.html · user-guide.html
└── README.md 
# from the PowerCodex repo root, copy into your project
cp -r tools/lifecycle /path/to/your-project/tools/lifecycle
No npm install needed — nothing here has third-party dependencies, so it won't touch your lockfile or node_modules.
3 Add the npm scripts

Wire it into package.json

Add these three scripts. They're thin wrappers over the CLI so your team runs the loop the same way everywhere.

"scripts": {
  "lifecycle": "node tools/lifecycle/bin/powercodex-lifecycle.js",
  "lifecycle:selftest": "node tools/lifecycle/bin/powercodex-lifecycle.js selftest",
  "lifecycle:init": "node tools/lifecycle/bin/powercodex-lifecycle.js init"
}
Pass CLI flags through npm with --, e.g. npm run lifecycle -- loop --rotations 3.
4 Initialize & ignore

Create the runtime folders

Run init once. It scaffolds the live workspace, the consent file, and a first dashboard snapshot.

npm run lifecycle:init

This creates two folders in your project root:

PathWhat it holdsCommit it?

*Commit it to share defaults with your team, or ignore it to keep grants per-machine. Never commit it with allowPush: true by accident.

Add to .gitignore

5 Grant rights

The consent gate is the whole safety model

Open Approved_rights/approval.json. Every flag defaults to false — the loop reads this file before it builds, pushes, or launches a browser, and stops and asks when a flag is off. Turn on only what you're comfortable letting it do.

{
  "browserProfile": "",              // Edge profile for the managed browser
  "allowBuild": false,            // may build app assets
  "allowPush": false,             // may push to the tenant
  "allowAutoRespec": false,       // may rewrite specs from observations
  "allowAutoApplyDefects": false,  // may auto-fix defects it finds
  "grantedBy": "user",
  "grantedAt": "2026-06-03"
}
Start narrow. A good first run sets allowBuild: true and leaves allowPush off — you watch it build and test in simulation, with nothing reaching a real tenant.
6 Watch it run

The desktop app + the loop

This is the daily rhythm. Open the desktop app, then drive the loop beside it.

The desktop app

Boots the lifecycle server on a free port and opens a Chat & Agent window that polls /api/state every 1.2s and re-renders in place.

The loop

npm run lifecycle -- loop --rotations 3
# the desktop app follows along live
Want to see it move before pointing it at real work? The loop runs in simulation by default (no --real), so the app visibly advances without touching a tenant.
7 Point it at your goal

Give it the two inputs

The loop runs around a goal (what the app should do, in plain language) and an approved MVP (the first slice). It measures everything against them with a live goal↔MVP compliance meter. As observations accumulate, each rotation's Observe stage authors defect / gap / improvement specs that feed the next Intake — that's the self-improving part.

To enhance an existing build, describe the goal as the next increment you want (the feature you're adding, the bug class you're hunting), let the loop plan and test against it, and read the authored specs as a prioritized worklist in the desktop app.

It composes with your existing setup. No Dataverse? The Build Executor falls back to running your app locally via npm run dev. Dataverse connected? It uses npx power-apps push + the app link. You don't restructure anything.
8 Go real

Swap two functions, change nothing else

By default both engines run in simulation — they emit the real event stream with simulated outcomes, so the whole loop and desktop app work without a tenant. When you're ready for the real thing, edit tools/lifecycle/lib/engines.js and replace the bodies of two functions with your Playwright-for-MDM adapters:

  • buildExecutor() — Engine 1: turns task contracts into portal assets via the managed Edge browser.
  • e2eTester() — Engine 2: runs end-to-end tests against the live app and drives the self-heal loop.

Keep the same signatures — both receive an emit callback and return the same result shape — and the orchestrator, gate, bus, and dashboard need no changes. Then run with --real:

npm run lifecycle -- loop --rotations 2 --real
# requires a tenant + the matching Approved_rights/ flags
The seam is deliberate. --real only does what the rights file allows — an un-approved build is blocked at the gate even in real mode.
9 Verify

Prove the integration is sound

Run the self-test. It executes the full loop in a throwaway workspace and asserts the product does what the plan promises — 16/16 checks.

npm run lifecycle:selftest
✓ All 7 stages emit
✓ Build assets created
✓ push-vs-dev rule honored
✓ A self-heal triggers
✓ An observation is authored
✓ Dashboard renders with brand
✓ /api/state returns 200 + JSON
✓ Rights gate blocks un-approved build

If all checks pass, the Lifecycle is wired in correctly. From here it's just the two-terminal rhythm from step 6, against whatever goal you're building toward.
